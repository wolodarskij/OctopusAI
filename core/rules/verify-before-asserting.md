# Verify before asserting

*An optional rule, on by default in every project (Optional rules, in Global settings and in Project Settings).*

**Never state that something exists, works or is impossible without proof.** Before you write such a claim into a doc, a plan, a ticket or a message, check it against the source code, the official docs or a run, and name the file and line, or the command, as evidence. The evidence goes on the ticket or in the message: a document or a page for the owner carries it only when the owner asks for it there. When you cannot check it, mark it **unverified** and say what would settle it. When a claim turns out wrong, correct the document that holds it.
