# Verify before asserting

*Always applies, in every project.*

**Never state that something exists, works or is impossible without proof.** Before you write such a claim into a doc, a plan, a ticket or a message, check it against the source code, the official docs or a run, and name the file and line, or the command, as evidence. When you cannot check it, mark it **unverified** and say what would settle it. When a claim turns out wrong, correct the document that holds it.
