# The owner's orders, in neutral words

*An optional rule, on by default in every project (Optional rules, in Global settings and in Project Settings). Governs every file: rules, skills, docs, tickets,
briefs, commit messages, comments and memory files.*

**No file holds a word-for-word quote of the owner, and no file holds the owner's swearing.** A file that records an
order of the owner states what the order requires, in neutral technical words. A rule, a skill, a brief, a
template and any other instruction or config file state only the rule: they never name who set the rule, or when.

- Write the order as a rule or a statement: "Change a README file only after the owner approved its exact new
  text." Do not copy the sentence that the owner wrote in chat.
- Give `--owner-order` and `--note` a neutral statement of the order, never the owner's message.
- Write an outcome line, a ticket, a `## Verified` note and a commit message in your own neutral words.
- When you find an owner quote or an owner's curse in a file, write it again as a neutral statement of the same
  order. Remove each curse, also in a misspelled form.

**Quote the owner word for word only when the owner explicitly asks for a quote.** Where the owner swore, never
quote, even on such a request.

**A project's own terms stay, even when they are crude.** A game, a level, an asset, a character or a mechanic that
the project's own content names that way keeps its name in the code, the assets, the docs and the tickets. Only the
owner's swearing at agents in chat is written again in neutral words.

Text that the owner writes as the author of a document, as in co-writing, is the owner's own text, not a quote. The
rule `owner-wording.md` governs it.
